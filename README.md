# ربات تلگرامی تخمین تراز سوابق و کنکور ۱۴۰۴ (رشته تجربی)

این ربات دقیقاً همون منطق فایل اکسل `taraz_estimator` رو پیاده‌سازی می‌کنه:
جست‌وجو و درون‌یابی (interpolation) در جدول واقعی کارنامه‌های ۱۴۰۴، و میانگین وزنی
با ضرایب رسمی سوابق/کنکور.

ورودی هر بخش **تک‌تک** پرسیده می‌شه — هر درس در یک پیام جداگانه، دقیقاً مثل
یه فرم قدم‌به‌قدم. فقط نتیجه‌ی نهایی (بدون ریز تراز هر درس) به‌همراه یه بازه‌ی
تخمینی نمایش داده می‌شه.

## فایل‌ها
- `taraz_bot.py` — کد اصلی ربات
- `taraz_data.json` — همون جدول‌های `Data_Sawabegh` و `Data_Konkur` که از اکسل استخراج شده
- `majors_tajrobi.json` — جدول رشته/دانشگاه‌های تجربی با آخرین رتبه‌ی قبولی هر کدوم (برای تخمین رشته)
- `users.json` — لیست شناسه‌ی کاربرهایی که `/start` زدن (برای Broadcast؛ خودکار ساخته می‌شه)
- `contact_map.json` — نگاشت پیام‌های فوروارد‌شده به ادمین برای قابلیت Reply (خودکار ساخته می‌شه)
- `requirements.txt`, `Procfile`, `railway.json`, `.gitignore` — فایل‌های پیکربندی دیپلوی

> نکته: اسم این ۴ تای آخر (`requirements.txt`, `Procfile`, `railway.json`, `.gitignore`)
> استاندارد و ثابته — پایتون، گیت و Railway دقیقاً با همین اسم‌ها دنبالشون می‌گردن،
> پس عمداً تغییرشون ندادیم. فقط دو فایل خودمون (`taraz_bot.py` و `taraz_data.json`)
> با پیشوند `taraz_` هم‌شکل شدن تا راحت‌تر پیدا بشن.

## قدم ۱: ساخت ربات در تلگرام
1. تو تلگرام به [@BotFather](https://t.me/BotFather) پیام بده.
2. دستور `/newbot` رو بزن و اسم/یوزرنیم دلخواه بده.
3. یک **توکن** بهت می‌ده، چیزی شبیه `123456:ABC-DEF...`. این رو نگه دار (جایی share نکن).

## قدم ۲: تست محلی (اختیاری)
```bash
python -m venv venv
source venv/bin/activate      # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
export BOT_TOKEN="توکنی که از BotFather گرفتی"   # ویندوز: set BOT_TOKEN=...
python taraz_bot.py
```
حالا تو تلگرام به ربات `/start` بزن.

## قدم ۳: آپلود روی گیت‌هاب
```bash
git init
git add .
git commit -m "taraz estimator telegram bot"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```
(⚠️ توکن ربات رو هیچ‌وقت داخل کد یا commit قرار نده — همیشه از environment variable استفاده کن؛ `.gitignore` هم `.env` رو نادیده می‌گیره.)

## قدم ۴: دیپلوی روی Railway
1. وارد [railway.app](https://railway.app) شو و با گیت‌هابت لاگین کن.
2. **New Project → Deploy from GitHub repo** و ریپوی همین پروژه رو انتخاب کن.
3. Railway به‌صورت خودکار `railway.json` / `Procfile` رو تشخیص می‌ده و `python taraz_bot.py` رو اجرا می‌کنه.
4. برو به تب **Variables** و متغیرهای زیر رو اضافه کن:
   - Key: `BOT_TOKEN` — Value: توکنی که از BotFather گرفتی
   - Key: `ADMIN_ID` — Value: شناسه‌ی عددی تلگرام خودت (پایین‌تر توضیح داده شده)
5. Deploy رو بزن. تو تب **Logs** باید ببینی `Bot starting (polling)...`.
6. حالا برو تو تلگرام و به ربات `/start` بزن.

> این ربات با «polling» کار می‌کنه (نه webhook)، پس نیازی به دامنه یا HTTPS نداری —
> فقط کافیه پروسه همیشه روشن بمونه، که روی Railway به‌صورت پیش‌فرض همینه.

## گرفتن ADMIN_ID (برای پیام پشتیبانی و Broadcast)
1. اول ربات رو بدون `ADMIN_ID` هم می‌تونی دیپلوی کنی (فقط این دو قابلیت غیرفعال می‌مونن).
2. تو تلگرام به ربات خودت پیام بده: `/myid`
3. یه عدد بهت می‌ده — همون رو به‌عنوان مقدار `ADMIN_ID` تو Variables بذار و Deploy رو دوباره بزن.

> ⚠️ فقط همون عدد رو بذار، بدون فاصله یا کاراکتر اضافه (نه یوزرنیم، نه `@`).
> اگه مقدار نامعتبر باشه، ربات دیگه کرش نمی‌کنه (این باگ رفع شده) — فقط
> قابلیت‌های پشتیبانی/Broadcast غیرفعال می‌مونن تا مقدارش رو درست کنی.

## قابلیت‌های ادمین
- **پیام پشتیبانی**: کاربرها از دکمه‌ی «✉️ ارسال پیام به پشتیبانی» می‌تونن متن
  یا عکس (با یا بدون کپشن) بفرستن، مستقیم برای `ADMIN_ID` فوروارد می‌شه
  (همراه با نام و شناسه‌ی فرستنده).
- **جواب دادن به کاربر**: کافیه رو همون پیامی که ربات از طرف کاربر برات فرستاده،
  تو تلگرام **Reply** بزنی و جوابت رو بنویسی — خودکار برای همون کاربر ارسال می‌شه.
  نیازی به دونستن شناسه‌ش نیست، فقط باید حتماً Reply باشه (نه پیام تازه).
- **Broadcast**: به ربات (به‌عنوان ادمین) دستور زیر رو بفرست تا برای همه‌ی
  کاربرهایی که تا حالا `/start` زدن ارسال بشه. دو روش داره:
  1. یه‌جا با متن: `/broadcast متن پیامی که می‌خوای بفرستی`
  2. یا فقط `/broadcast` رو تنها بفرست، ربات ازت می‌پرسه چی می‌خوای بفرستی —
     می‌تونی متن، عکس یا **ویدیو** (با یا بدون کپشن) رو تو پیام بعدی بفرستی.
  فقط شناسه‌ی برابر با `ADMIN_ID` اجازه‌ی استفاده از این دستور رو داره.
- **آمار کاربرها**: دستور `/stats` رو بفرست تا تعداد کل کاربرهایی که تا الان
  `/start` زدن رو ببینی. فقط `ADMIN_ID` می‌تونه از این دستور استفاده کنه.

> ⚠️ لیست کاربرها تو فایل `users.json` ذخیره می‌شه. اگه یه Volume به سرویس
> وصل نکرده باشی، این فایل روی دیسک موقت کانتینر Railway می‌مونه که با هر
> Redeploy (مثلاً بعد از هر آپلود کد جدید) **پاک می‌شه** و لیست کاربرها صفر
> می‌شه. برای اینکه این لیست همیشگی بمونه:
> 1. یک **Volume** به سرویس وصل کن (تب Settings سرویس → Volumes → New Volume)
>    و مسیرش (Mount Path) رو مثلاً `/app/data` بذار.
> 2. تو Variables یه متغیر جدید بساز: `DATA_DIR` با مقدار `/app/data`
>    (دقیقاً همون مسیری که تو مرحله‌ی قبل گذاشتی).
> بعد از این کار، `users.json` و `contact_map.json` تو همون Volume ذخیره
> می‌شن و با آپدیت‌های بعدی از بین نمی‌رن.

## نکات محاسباتی (برای شفافیت)
- تراز هر درس از روی جدول واقعی کارنامه‌ها (نه فرمول آماری) با درون‌یابی خطی به دست میاد؛ فقط تراز نهایی به کاربر نشون داده می‌شه، نه ریز هر درس.
- تراز سوابق = میانگین وزنی تراز ۱۰ درس با ضرایب رسمی سوابق.
- تراز کنکور (اختصاصی) = میانگین وزنی تراز ۴ یا ۵ درس تخصصی؛ زمین‌شناسی اختیاریه.
- تراز نهایی = ۶۰٪ سوابق + ۴۰٪ کنکور اختصاصی (طبق سهم اعلامی ۱۴۰۴)، بدون احتساب دروس عمومی حذف‌شده — این عدد صرفاً یک تخمینه.
- **بازه‌ی تخمینی خوش‌بینانه**: به‌جای یک عدد خام، یه بازه نشون داده می‌شه که سمت بالاش بیشتر از سمت پایینش کشیده شده (چون کنکور ۱۴۰۴ سخت بوده و درصدهای عمومی پایین‌تر از قبل بوده). این ضریب‌ها تو کد قابل تنظیمن: `SAWABEGH_MARGIN_PERCENT`, `KONKUR_MARGIN_PERCENT`, `FINAL_MARGIN_PERCENT`, `OPTIMISM_SKEW`.
- **رتبه‌ی تخمینی**: فعاله ✅ — وقتی کاربر هردو بخش (سوابق + کنکور) رو حساب کنه،
  ربات ازش منطقه‌ی کنکور (۱، ۲ یا ۳) رو می‌پرسه و یه بازه‌ی رتبه‌ی تخمینی
  بر اساس کارنامه‌های واقعی همون منطقه نشون می‌ده. این محاسبه هم مثل تراز، با
  درون‌یابی خطی رو جدول واقعی تراز-به-رتبه انجام می‌شه (نه فرمول آماری).
- **رشته‌های احتمالی قبولی**: فعاله ✅ — بعد از گرفتن بازه‌ی رتبه، ربات می‌پرسه
  آیا رشته‌های احتمالی رو هم نشون بده. اگه بله، از `majors_tajrobi.json`
  رشته‌هایی که آخرین رتبه‌ی قبولی‌شون با بازه‌ی رتبه‌ی کاربر هم‌پوشانی داره رو
  ۴ دسته می‌کنه — بازه‌ی رتبه‌ی کاربر (بهترین تا بدترین حالت) به ۴ منطقه تقسیم می‌شه:
  - 🟢 **قطعی**: حتی با بدترین حالت بازه هم قبول می‌شه (رتبه‌ی مرزی ≥ بدترین حالت)
  - 🔵 **محتمل**: رتبه‌ی مرزی تو نیمه‌ی بالای بازه‌ست (نزدیک‌تر به بدترین حالت)
  - 🟡 **ریسکی**: رتبه‌ی مرزی تو نیمه‌ی پایین بازه‌ست (نزدیک‌تر به بهترین حالت)
  - 🟠 **بعید**: کمی پایین‌تر از بهترین حالت بازه‌ست، شانس کمی داره ولی کاملاً غیرممکن نیست
  حداکثر ۸ مورد از هر دسته نشون داده می‌شه (`MAJORS_MAX_PER_CATEGORY` در کد)،
  تو ۲ پیام جدا (برای اینکه از سقف طول پیام تلگرام رد نشه).
- **ابزار انتخاب رشته با رتبه‌ی دقیق**: فعاله ✅ — گزینه‌ی «🎓 انتخاب رشته
  (رتبه‌مو می‌دونم)» تو منوی اصلیه، برای کسایی که رتبه‌ی واقعی‌شون رو از قبل
  می‌دونن (مثلاً بعد از اعلام نتایج) و نمی‌خوان از اول سوابق/کنکور رو حساب کنن.
  فقط منطقه و رتبه رو می‌پرسه، همون ۴ دسته (قطعی/محتمل/ریسکی/بعید) رو نشون
  می‌ده. چون این‌جا رتبه‌ی کاربر دقیقه (نه یه بازه‌ی تخمینی)، دسته‌بندی بر
  اساس نوسان احتمالی رتبه‌ی مرزی هر رشته نسبت به سال قبل انجام می‌شه
  (±۵٪ حول رتبه‌ی مرزی هر رشته — `RANK_TOOL_MARGIN_PERCENT` در کد).
- **ابزار انتخاب رشته با تراز**: فعاله ✅ — گزینه‌ی «🏆 انتخاب رشته (ترازمو
  می‌دونم)» تو منوی اصلیه، برای کسایی که فقط تراز کلشون رو دارن (نه رتبه).
  ربات اول منطقه رو می‌پرسه، بعد تراز رو می‌گیره، خودش با همون جدول
  تراز-به-رتبه یه رتبه‌ی تخمینی می‌سازه و می‌گه، و بعدش دقیقاً با همون منطق
  «ابزار رتبه‌ی دقیق» بالا، ۴ دسته‌ی رشته رو نشون می‌ده.
- **جستجوی رتبه‌ی قبولی یه رشته با اسمش**: فعاله ✅ — گزینه‌ی «🔍 جستجوی
  رتبه‌ی قبولی یه رشته» برعکسِ ۳ ابزار بالاست: کاربر اسم رشته رو می‌نویسه
  (کامل یا بخشی ازش، مثلاً «پرستاری»)، ربات تو `majors_tajrobi.json` جست‌وجو
  می‌کنه و لیست دانشگاه‌هایی که اون رشته رو دارن رو با رتبه‌ی مرزی هر ۳ منطقه
  (+ تراز تخمینی هرکدوم) نشون می‌ده. حداکثر ۲۰ نتیجه‌ی اول (مرتب‌شده بر اساس
  رقابتی‌ترین رتبه‌ی منطقه‌ی ۳) نمایش داده می‌شه — اگه بیشتر بود، تعداد
  باقی‌مونده رو می‌گه و پیشنهاد می‌ده اسم دقیق‌تری بنویسه.
  این گزینه بیشتر برای اشتراک‌گذاری تو کانال مناسبه: کاربر از کانال وارد پیوی
  ربات می‌شه و مستقیم رشته‌ی موردنظرش رو جست‌وجو می‌کنه، بدون نیاز به محاسبه‌ی
  تراز یا رتبه‌ی خودش.
- **فیلتر نوع دوره + شهر/دانشگاه** (اضافه‌شده به هر ۴ ابزار بالا): فعاله ✅ —
  درست قبل از نمایش نتیجه، ربات دو تا سوال اضافه می‌پرسه:
  1. **نوع دوره**: یکی از سه گزینه رو انتخاب می‌کنی —
     «فقط روزانه (رایگان)»، «دولتی (روزانه+شبانه+پردیس و مشابه)»،
     یا «همه‌ی دوره‌ها (شامل غیرانتفاعی/پیام‌نور/آزاد)». پیش‌فرض‌ها تو
     `COURSE_PRESETS` در کد قابل تغییرن.
  2. **شهر/دانشگاه** (اختیاری): می‌تونی اسم یه شهر یا بخشی از اسم دانشگاه
     رو بنویسی (مثلاً «تهران») تا فقط نتایج همون‌جا نشون داده بشه، یا دکمه‌ی
     «نه، همه‌جا رو نشون بده» رو بزنی.
  این دو فیلتر رو هر دفعه (بعد از هر بار محاسبه یا جستجو) دوباره می‌پرسه،
  به‌جز تو ابزار جستجوی نام رشته که فقط یه‌بار در ابتدای اون مسیر می‌پرسه و
  تا وقتی /start نزنی، برای همه‌ی جستجوهای بعدی همون فیلترها اعمال می‌مونه.

## به‌روزرسانی داده‌ها در آینده
اگه بعداً جدول‌های منبع (کارنامه‌های واقعی) به‌روز شدن، کافیه `taraz_data.json` رو با
داده‌ی تازه جایگزین کنی؛ ساختار باید همون کلیدهای `sawabegh_headers`,
`sawabegh`, `konkur_headers`, `konkur`, `rank_by_region` رو حفظ کنه.
`rank_by_region` یه دیکشنریه با کلیدهای `region1`, `region2`, `region3` که
هرکدوم لیستی از `[تراز, رتبه]` هستن (صعودی بر اساس تراز).
